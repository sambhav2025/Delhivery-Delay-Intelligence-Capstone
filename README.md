# Delhivery-Delay-Intelligence-Capstone
IIT Roorkee Capstone Project

Delhivery Last-Mile Delay Intelligence PipelineA unified machine learning and operational intelligence pipeline built for Delhivery's regional operations team to forecast parcel delivery hours, flag potential delays prior to breach, segment hub operational behavior, and generate actionable dispatch-time playbooks.1. Production PlanOperational Readiness ArchitectureConsistency: Preprocessing logic is encapsulated strictly within src/shipment_prep.py (clean_shipments and build_features), guaranteeing identical transformations across training, evaluation, and production batch scoring.Reproducibility: All train/test splits, model fits, and cluster initializations utilize pinned seed parameters (random_state=42).Maintainability: Modular separation between baseline ingestion (part_a), regression modeling (part_b), classification (part_c), hub segmentation (part_d), packaging (package_model.py), and prediction inference (predict_delay.py).Performance: Pipeline execution for batch scoring (48 parcels) processes in $< 0.15$ seconds offline using optimized vectorized pandas and scikit-learn primitives.Reliability: Missing data imputation values (models/impute_values.csv) are calculated strictly from training baseline distributions and persisted to prevent runtime failure during inference gaps.Monitoring & Drift DetectionWeekly Metrics Monitored:Observed Delay Rate: Alert trigger if actual weekly delay rate exceeds baseline threshold of 0.2500 (+8% shift).Flagged Parcel Ratio: Alert trigger if proportion of shipments flagged by inference pipeline exceeds 0.3000.Production Recall: Evaluated on 14-day trailing completed shipments; alert trigger if rolling recall drops below 0.7000.Retraining Schedule & Sale Events:Models must be retrained monthly or immediately following major network restructuring.Festival/Sale Windows (sale_event_flag = 1): Historical performance during festive windows (e.g., Sept 15–28) shows a mean baseline delay shift of +12.0 hours. Retraining must evaluate festival periods against historical sale windows rather than standard off-peak operational weeks.7. LimitationsSynthetic Data Boundaries: The dataset is generated via synthetic parameterized distributions (generate_data.py), which may under-represent complex multi-node network bottlenecks present in real-world logistics.Sample Size Limitations in Test Set: The test partition contains exactly 41 delayed shipments, meaning a small shift of 2–3 misclassifications causes a ~5–7% change in reported test recall.Static Thresholding: The decision threshold ($t = 0.5$) was optimized against a single validation split; continuous dynamic thresholding based on live hub capacity is recommended for full production deployment.
